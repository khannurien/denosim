# Public API

Current state of what `mod.ts` exports: 76 symbols, 21 functions and the types they use; the examples use 23 of them.
Signatures are given without their type parameters; terms are defined in `VOCABULARY.md`.
The last column flags what is awkward or wrong.

## Setting up a simulation

| Export                                                    | Does today                                                                                                                                                                                                                                        | To fix                                                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `initializeSimulation(): Simulation`                      | Empty simulation at time `0`, with the `none` process and the `FIFO` and `LIFO` disciplines                                                                                                                                                       |                                                                                                          |
| `Simulation<S>`                                           | A simulation typed by its stores, `S` mapping each store ID to its items: written with them, `{ ...initializeSimulation(), stores: { id: initializeStore(options) } }`; each item type is inferred from `S`, and no store can be missing or added |                                                                                                          |
| `registerProcess(sim, definition): ProcessRegistry`       | Returns the registry with the definition added; the caller assigns it to `sim.processes`; the stores the definition declares must be those of `sim`                                                                                               |                                                                                                          |
| `registerDiscipline(sim, definition): DisciplineRegistry` | Same, for `sim.disciplines`                                                                                                                                                                                                                       |                                                                                                          |
| `registerPredicate(sim, definition): PredicateRegistry`   | Same, for `sim.predicates`                                                                                                                                                                                                                        |                                                                                                          |
| `initializeStore(options): Store`                         | Builds an empty store: `capacity`, `discipline` for its items and `consumerDiscipline` for its blocked consumers, each a built-in key or a definition; it holds no ID and is not added to the simulation                                          | `initialize` here, `create` in `CreateStoreOptions` and `createEvent`                                    |
| `registerStore(sim, id, store): StoreRegistry`            | Returns the stores with this one added under `id`, one of the IDs `sim` declares; the caller assigns it to `sim.stores`, a handler included                                                                                                       | A store dropped by a handler stays in the states rebuilt from the history: deltas do not record removals |
| `createEvent(options): Event`                             | Builds an event: `scheduledAt`, and optionally `parent`, `process`, `priority`, `waiting`; does not add it to the timeline                                                                                                                        |                                                                                                          |
| `scheduleEvent(sim, event): Timeline`                     | Returns the timeline with the event added; throws `RangeError` if `scheduledAt` is in the past; the caller assigns it to `sim.timeline`                                                                                                           |                                                                                                          |

## Running

| Export                                                    | Does today                                                                                                                                                                                | To fix                                                                                   |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `runSimulation(sim, options?): Promise<SimulationResult>` | Handles events until none is left, or until `until` returns `true`; `sim` is left untouched; the result and its history are typed by the stores of `sim`                                  |                                                                                          |
| `RunSimulationOptions.until`                              | `(sim, next) => boolean`, checked before `next` is handled; when `true` the run stops and `next` stays `Scheduled`                                                                        | With a `rate` it is called twice per event: no side effect                               |
| `RunSimulationOptions.signal`                             | `AbortSignal`: stops the run from outside, including during the wait before an event; the clock stops where the wait did                                                                  | Only seen while the run waits                                                            |
| `RunSimulationOptions.rate`                               | Simulation time units per wall-clock second: the run waits before each event                                                                                                              | Without it, or a `directory`, the loop never yields: nothing outside can ask for a pause |
| `RunSimulationOptions.history`                            | `HistoryOptions`: `directory`, `interval` (handled events per window, `1000` by default), `metadata`                                                                                      |                                                                                          |
| `SimulationResult`                                        | `result` (final simulation, complete), `stats`, `next` (the event the run stopped before) when `until` or `signal` ended it, and `history` (the windows) when asked without a `directory` |                                                                                          |
| `SimulationStats`                                         | `end` (simulation time), `duration` (wall-clock milliseconds)                                                                                                                             |                                                                                          |

What a run does today, checked by running it:

- Nothing is written to disk without `history.directory`; the examples run with no permission;
- `until: (_sim, next) => next.scheduledAt > T` handles every event at or before `T`, and none after;
- The working state is compacted every 100 handled events, whether the history is kept or not; the returned simulation is complete, as if nothing had been pruned;
- With a `directory`, each window is a dump `dumps/<count>-t<time>.json`, next to `run.json`; a run in a directory that already holds dumps adds its own after them.

## Pausing, resuming, branching, rewinding

| Need    | Done today with                                                                                                                                                      | To fix                                                         |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Pause   | `until`: on a time, on the next event, on any state; `signal`: from outside, at any wall-clock time when the run has a `rate`                                        |                                                                |
| Resume  | `runSimulation(result)`: same end as an uninterrupted run, before any event                                                                                          |                                                                |
| Branch  | One copy `{ ...paused }` per branch, `scheduleEvent` or another registry on each, one run each; `paused` is left untouched; `reorderStore` after a discipline change | Two branches in one `directory` interleave their windows       |
| History | `history: {}` returns the windows; `history: { directory }` writes them, `loadHistory<S>(directory, sim)` reads them back; `S`, when given, types their stores       | A resumed run returns its own windows: the caller concatenates |
| Rewind  | `historyStates(windows)[k]`: the state after `k` handled events, complete; windows of a resumed run follow those of the first                                        | Builds every state: quadratic in memory                        |
| Save    | `serializeSimulation(sim)`: registries left out                                                                                                                      |                                                                |
| Restore | `deserializeSimulation<S>(json, sim)`: registries taken from any simulation holding them; `S`, when given, types the stores                                          | The JSON is trusted to hold these stores                       |
